# framework-sdk-java 测试审查

对每个测试给出「保留、改写、合并或删除」的结论，并指出它保护的公开不变量。

- 保留：缺陷复发时能失败，覆盖公开 API、错误码与消息键、取消与截止时间、并发、容量上限、生命周期次序或线上编码。
- 改写：只断言内部方法被调用、依赖私有字段或线程调度、用 sleep 等待时钟或信号、没有失败路径。
- 合并：与相邻用例输入和断言等价，不提供额外定位。
- 删除：不可能失败、只验证常量或 JDK 本身，或已被向量回放完整覆盖。

## 本仓库的重点

- 向量回放（`*VectorsTest` 与回放向量的其他测试）逐条断言期望值，不跳过向量里的用例；`VectorCoverageTest` 的 `REPLAYED` 与实际回放的文件一致，`GAPS` 每条都有理由。
- 截止时间与取消的测试直接触发令牌（如 `DeadlineSignals`），不靠真实等待；并发测试断言可观察的不变量，不依赖固定延时。
- 插件运行时的测试区分进程内（`RunningPlugin`）与黑盒运行器（`EchoConformanceTest`）；`EchoConformanceTest` 的 `CASES` 与规范运行器的用例一致，缺 Go 时失败而不是静默跳过。
- 容量测试覆盖到达上限与超出上限。
- 断言消息与夹具文本是英文。

输出按风险排序，附文件与行号。除非用户要求运行，否则只做静态审查；不通过删除测试或放宽门禁解决生产缺陷。
